# Партнёры — денежная рефералка

Обычная рефералка платит днями: другу 3 дня, пригласившему +3 дня сразу и +7 после первой
оплаты друга, раз в месяц лучшему — год. **Партнёр** — пользователь, которому админ
выборочно заменил её на деньги: с каждой рублёвой оплаты приглашённого друга ему идёт
процент на баланс, баланс выводится по СБП или тратится на свою подписку.

## Правила

| Правило | Как реализовано |
|---|---|
| Кто партнёр | Назначает админ: `/admin` → «🤝 Партнёры» → «➕ Сделать партнёром» (Telegram ID или @username; человек должен хоть раз запустить бота) |
| Ставка | 30% по умолчанию (`partner_percent` в `app_settings`), у партнёра может быть персональная (`partners.percent`) — она важнее общей |
| Что считается | Каждая оплата друга, бессрочно: покупка и продление тарифа (вместе со слотами и трафиком на чекауте), автосписание, «свои дни» у менеджера (`kind` = `subscription`/`custom`) |
| Что не считается | Отдельная докупка слотов/трафика (`kind` = `devices`/`traffic`), Telegram Stars, оплата с партнёрского баланса (`source='balance'`). Услуга менеджера в продаже — деньги менеджера, процент с неё не берётся |
| Какие друзья | Только пришедшие по ссылке, пока партнёр был активен (`users.partner_referred`). Приглашённые раньше не считаются |
| Другу | Тот же триал 3 дня, что и в обычной рефералке |
| Партнёру | Никаких бонусных дней (ни +3, ни +7), в лидерборде не участвует |
| Холд | Начисление доступно через `partner_hold_days` (14) дней после оплаты друга; переводит джоб `release_partner_holds` (в :07 и :37) |
| Возврат оплаты друга | В холде — начисление отменяется; после холда — списывается с баланса, но **баланс не уходит ниже нуля** (списывается сколько есть) |
| Вывод | По СБП (телефон + банк, вводятся один раз), от `partner_min_withdrawal` (500 ₽), одна заявка за раз. Сумма списывается с баланса сразу; админ переводит руками и жмёт «Выплачено» или «Отклонить» (причина кнопкой) — при отказе деньги возвращаются |
| Оплата подписки с баланса | Только целиком: тариф + уже купленные слоты и трафик (как автопродление, `PaymentService.renewal_quote`). Проводится через обычный конвейер: `Payment(source='balance', yookassa_payment_id='balance:<user>:<nonce>')` → `process_successful_payment`. В выручку не входит |
| Отключение | Новые начисления прекращаются (и с уже приглашённых друзей), друзья снова приводят дни по обычной программе; накопленный баланс и заявки остаются — кнопка «💰 Партнёрский баланс» на экране рефералки |

## Где что

| Файл | Что внутри |
|---|---|
| `tgbot/services/partner_rules.py` | Чистые функции: что считается, процент в копейках (вниз), формат ₽, разбор суммы и телефона |
| `tgbot/services/partner_service.py` | Вся логика: начисление/сторно (зовёт `PaymentService`), холд, вывод, оплата с баланса, админка |
| `tgbot/services/partner_notifier.py` | Сообщения партнёру, заявки в топик выплат, лог оплаты с баланса |
| `database/repositories/partner.py` | Атомарные операции с балансом: условный `UPDATE … WHERE balance_kop >= x` + запись в журнал одной транзакцией |
| `tgbot/handlers/user/partner.py` | Экран партнёра в боте (`pt:*`): баланс, вывод, оплата, история, реквизиты |
| `webapp/routers/partner.py` | То же на сайте (`/profile/partner`) и в Mini App (`/tma/partner`): формы + PRG, проверка Origin |
| `webapp/templates/partner/` | `_panel.html` — общее тело кабинета, `_card.html` — карточка в `/profile/`; обёртки `partner.html`, `tma/partner.html` |
| `tgbot/handlers/admin/partners.py` | Админка (`admin_pt*`) и кнопки заявок (`pw_*`) — работают и в топике, и в админке |
| `tests/test_partner.py` | Интеграционные тесты на SQLite с настоящим `PaymentService` |
| `tests/test_partner_web.py` | Сайт и Mini App по HTTP: регистрация по `?ref=`, оплата веб-друга → процент, кабинет партнёра |
| `tests/test_admin_money_stats.py` | Долг партнёрам и продажи менеджеров в статистике |

Партнёрский экран открывается по «👥 Пригласить друга» и `/referral` в боте (в режиме `UI_MODE=tma` эта
кнопка у партнёров открывает `/tma/partner`).

## Кабинет партнёра на сайте и в Mini App

`/profile/partner` (сайт, вход — карточка «Партнёрская программа» в `/profile/`) и `/tma/partner`
(Mini App, вход — `/tma/referral`) умеют всё, что экран в боте: баланс, холд, приглашённые и оплатившие,
ссылки для друзей (бот `?start=ref<id>`, сайт `/register?ref=<id>`), реквизиты СБП, заявку на вывод,
оплату подписки с баланса (вторым экраном `?pay=<тариф>` с nonce — повтор формы не спишет дважды),
историю. Логика — тот же `partner_service`; роутер только принимает формы и отвечает редиректом
с кодом итога (`?ok=` / `?err=`, текст из словарей — параметр в разметку не попадает).
POST проверяют Origin поверх SameSite-cookie (`webapp/core/origin.py`): подменить реквизиты с чужого
сайта нельзя. Отключённому партнёру кабинет открыт, пока у него есть деньги в программе.

Партнёром можно сделать и веб-пользователя (отрицательный id; в админке поиск по ID, @username или email) — уведомления бота ему не придут, всё видно в кабинете на сайте.
Друзья приходят откуда угодно: регистрация на сайте по `/register?ref=<id>` привязывает реферера тем же
`referral_service.attach_referrer`, что и `/start` в боте (и ставит `partner_referred` другу активного
партнёра), Mini App — по `startapp=<id>` при первом входе.

## Статистика

`/admin` → «📊 Статистика» → «Долг партнёрам» = балансы + начисления в холде + заявки на вывод, которые
ещё не выплачены (с баланса они уже списаны) — `PartnerRepository.debt_summary`.

## Данные

- `partners` — `user_id` (PK), `status` (`active`/`disabled`), `percent`, `balance_kop` (доступно),
  `sbp_phone`, `sbp_bank`.
- `partner_ledger` — журнал: `accrual` (+, статус `hold`/`available`/`cancelled`/`reversed`),
  `reversal`, `withdrawal`, `withdrawal_return`, `spend`, `spend_return`. `UNIQUE(kind, payment_id)` —
  идемпотентность против повторных вебхуков и двойных нажатий.
- `partner_withdrawals` — заявки (`pending`/`paid`/`rejected`), снимок реквизитов, сообщение в топике.
- `users.partner_referred` — друг пришёл по ссылке активного партнёра.

Деньги — в копейках (целые). В холде — сумма `accrual` со статусом `hold`, на балансе — `partners.balance_kop`.

## Деплой

```bash
python3 fix_db.py        # секция 22: users.partner_referred + новые таблицы — ДО перезапуска бота
./refresh.sh
```

Без миграции бот упадёт на первом запросе к `users`: колонка `partner_referred` уже есть в модели.

В `.env`: `PARTNER_PAYOUT_TOPIC_ID=31` — топик в `SUPPORT_CHAT_ID` для заявок на вывод
(не задан — заявки идут в топик лога транзакций). Нажимать кнопки заявки может только админ из `ADMINS`.
