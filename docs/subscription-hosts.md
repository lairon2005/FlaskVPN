# Порядок хостов в подписке и авто-выбор сервера

Применено к панели **01.10.2026** (Remnawave 3.4.4). Всё делает
`scripts/remnawave_host_order.py` — запускается **на хосте панели**.

## Что видит пользователь

Порядок в подписке (15 строк при 4 нодах):

| # | Что | Строки |
|---|---|---|
| 1–3 | Авто-выбор | `✴️ Авто (Основные)`, `✴️ Авто (Запасные)`, `✴️ Авто (Турбо)` |
| 4–7 | Основные | Германия / Польша / Германия 2 / Нидерланды |
| 8–11 | Запасные | те же четыре страны |
| 12–15 | Турбо | те же четыре страны |

Внутри группы порядок стран прежний (по `view_position`). «Авто» — клиент сам выбирает из
группы сервер с лучшим пингом, выбирать страну руками не нужно.

## Оформление названий

Метки взяты из бренд-бука (`brand.md`): синий — основной цвет, голубой — второй, оранжевый —
акцент, «искра»-астериск — фирменный графический элемент. Прежние ромбики `🔶🔸` и `⚡`
были скопированы с vacvpn.

| Группа | Метка | Цвет бренда | Пример |
|---|---|---|---|
| Основные | `🔵` | глубокий синий `#2457C5` | `🇩🇪 🔵 Основной (Германия)` |
| Запасные | `🔹` | светлый голубой `#73B9F5` | `🇩🇪 🔹 Запасной (Германия)` |
| Турбо | `🟠` | оранжевый `#FF7627` | `🇩🇪 🟠 Турбо (Германия)` |
| Авто-выбор | `✴️` | оранжевая «искра» | `✴️ Авто (Основные)` |

Метки — в `GROUPS` и `AUTO_EMOJI` скрипта; поменять и запустить `--apply`, старая метка
(в том числе vacvpn) убирается сама. Цвет эмодзи на клиенте зависит от платформы: у голубого
`🔹` оттенок не совпадает с `#73B9F5` точно — это ограничение эмодзи.

## Как устроено

- **Группа хоста определяется словом в названии:** `Основной` → тег `MAIN`, `Запасной` →
  `RESERVE`, `Турбо` → `TURBO`. Скрипт проставляет теги сам. Название нового хоста обязано
  содержать это слово, иначе он окажется в конце списка вне групп (скрипт об этом предупредит).
- **Авто-хост** — клон первого хоста группы с тем же тегом и своим XRAY_JSON-шаблоном
  `Auto-Select` (`hosts.xray_json_template_uuid`). Скрипт отличает авто-хосты от
  настоящих по этому шаблону, а не по названию.
- **Шаблон `Auto-Select`** — копия `Default` (с правилами `ANTI-DETECT-*`) плюс:
  - `remnawave.injectHosts` с селектором `sameTagAsRecipient` и `selectFrom: ALL` — в конфиг
    попадают все хосты с тем же тегом, что у авто-хоста, как outbound'ы `proxy`, `proxy-2`, …;
  - `observatory` (проба `https://www.gstatic.com/generate_204` раз в 60 с);
  - балансировщик `auto` (`leastPing`, `fallbackTag: proxy`, селектор `proxy`) и последнее
    правило `AUTO-SELECT` → `balancerTag: auto`.
- **Только JSON-подписка.** Авто-хосты исключены из `XRAY_BASE64`, `MIHOMO`, `STASH`, `CLASH`,
  `SINGBOX` (`exclude_from_subscription_types`): без балансировщика это был бы дубль одного
  сервера. Клиентам, которые берут base64/clash, авто-выбор не показывается.
- **Запись идёт в БД, не через API:** API 3.x вырезает из шаблона `remnawave`, `observatory` и
  `routing.balancers`. После записи — `docker restart remnawave` (API молчит ~20 с).
  Если позже править шаблон `Auto-Select` через UI панели, эти секции пропадут — запускай
  скрипт заново.

## Как добавить ноду

Заведи три хоста с названиями вида `🇫🇷 Основной (Франция)`, `🇫🇷 Запасной (Франция)`,
`🇫🇷 Турбо (Франция)` (метку группы скрипт поставит сам) и запусти скрипт повторно: он проставит теги, расставит порядок и
оставит существующие авто-хосты (`keep`). Новая нода автоматически войдёт в авто-выбор своей
группы.

```bash
scp scripts/remnawave_host_order.py FlaskVPN_Remnawave_Panel:/root/host_order.py
ssh FlaskVPN_Remnawave_Panel python3 /root/host_order.py            # dry run
ssh FlaskVPN_Remnawave_Panel python3 /root/host_order.py --apply    # бэкап -> запись -> restart
ssh FlaskVPN_Remnawave_Panel python3 /root/host_order.py --revert   # откат из последнего бэкапа
```

Откат возвращает `view_position` и теги из JSON-бэкапа, удаляет авто-хосты и шаблон
`Auto-Select`. Бэкап перед применением 01.10.2026 — в `/root/rw-backups/`:
`host-order.pre.20261001_103815.json` и `hosts_templates.pre-host-order.20261001_103815.sql`
(до первого применения; повторное, с авто-хостами наверху, — `…_104328`).

## Проверка выдачи

Панель отдаёт заглушку «App not supported» запросу без `x-hwid` (у нас включён лимит
устройств) — поэтому проверять нужно с заголовками клиента. **Такой запрос регистрирует
устройство** на пользователе: тестовый hwid после проверки удаляй.

```bash
curl -s -A 'Happ/5.7.0/ios/2609021014549' -H 'x-hwid: test-hwid-0001' -H 'x-device-os: iOS' \
  https://sub.flaskvpn.ru/<short_uuid>/json | python3 -c "import sys,json;print([c['remarks'] for c in json.load(sys.stdin)])"
docker exec -i remnawave-db psql -U postgres -d postgres -c "delete from hwid_user_devices where hwid='test-hwid-0001'"
```

Проверено 01.10.2026: 15 конфигов, три авто-хоста первыми; в каждом авто-конфиге по 4 outbound'а
группы, балансировщик и `observatory`; `xray -test` на ноде принимает все три конфига.

## Что не проверено

- **Поведение на устройстве.** Не смотрели, как INCY и Happ показывают строку с балансировщиком
  и действительно ли переключаются между серверами по пингу. Возможен вариант, что клиент
  ведёт себя иначе (например, показывает пинг только до первого outbound). Проверить на
  Android и iOS.
- **HY2 в балансировщике.** Турбо-хосты — Hysteria2 (UDP); Xray принимает такой outbound в
  `leastPing`, но живую пробу через UDP-хост на клиентах не проверяли.
- Обновление у пользователей — при ближайшем обновлении подписки (`profile-update-interval`
  у нас 12 часов).
