# Менеджеры офлайн-продаж, свои дни, временные ключи, докупка трафика

Менеджер — человек, который офлайн продаёт и устанавливает VPN. Своя панель — в боте
(`/manager`) и на сайте (`/manager`). Всё считает и проверяет один сервис
`tgbot/services/manager_service.py`; хендлеры бота и роуты сайта — тонкие.

## Роли

| | Менеджер | Админ |
|---|---|---|
| Выдать по тарифу / свои дни / временный ключ | если право включено | через админку как раньше |
| Принять наличные | только `can_accept_cash` и в пределах `cash_limit` | принимает выручку |
| Видеть клиента | только с рабочим доступом, только поля `ClientCard` | всё |
| История, статистика | только свои | все + CSV |
| Общая статистика | только `can_view_global_stats` | да |
| Тарифы, цены, формула, настройки, менеджеры, VPN-инфраструктура | нет | да |

Права и лимиты задаёт админ: «👔 Менеджеры» в `/admin`. Любая смена прав, блокировка и
удаление сбрасывают веб-сессии менеджера (`session_version`), а мутирующие действия каждый
раз перечитывают менеджера из БД — блокировка действует мгновенно, без ожидания кэша.

## Как заводится менеджер

1. Админ: `/admin` → «👔 Менеджеры» → «➕ Пригласить» → имя → **логин для сайта**. Бот выдаёт ссылку
   `t.me/<бот>?start=mgr_<токен>` — одноразовая, 24 часа, в БД только sha256 токена.
2. Менеджер переходит по ссылке → становится `active`, получает команду `/manager`
   и кнопку «👔 Панель менеджера» в главном меню, а следом — ссылку «задать пароль».
3. Один Telegram-аккаунт — один менеджер. Удаление мягкое (`status='deleted'`): журнал и
   чеки остаются навсегда, логин освобождается.

## Вход на сайт: логин и пароль

- **Логин** назначает админ (при приглашении или в карточке «🔤 Логин для сайта»): латиница, цифры,
  `.`/`_`/`-`, 3–32 символа, первая — буква, хранится в нижнем регистре, уникален. Менеджеру,
  заведённому до появления логинов, админ задаёт логин в карточке — ссылка на пароль уйдёт ему сама.
- **Пароль** знает только менеджер: задаёт по одноразовой ссылке из бота (`/manager/password?t=…`,
  30 мин, в БД sha256). Ссылку бот шлёт после принятия приглашения, по кнопке «🌐 Вход на сайт» →
  «🔑 Задать/Сменить пароль» и после сброса админом. Хранится argon2. Не короче 8 символов, без логина.
- **Сайт**: `/manager/login`, галочка «Запомнить меня» — сессия на 30 дней, без неё — 12 ч и до закрытия
  браузера. Смена пароля на сайте — «Аккаунт» (имя в шапке), нужен текущий пароль.
- **Защита**: 5 неверных паролей подряд → вход по логину закрыт на 15 мин (и уведомление менеджеру);
  с одного IP — не больше 20 неудач за 15 мин по всем логинам. Ответ на «нет такого логина» и
  «неверный пароль» одинаковый. О каждом входе менеджеру приходит сообщение в бот (время, IP,
  браузер) с кнопкой «🚪 Это не я — завершить все входы».
- **Сброс**: админ → карточка → «🔑 Сбросить пароль»: пароль стёрт, все сессии закрыты, менеджеру
  уходит ссылка на новый. Установка/смена пароля тоже закрывает все прежние сессии.
- Входа по одноразовой ссылке больше нет.

## Клиенты и приватность

Менеджер не ищет клиентов по Telegram ID, username или email — чужую базу так не разведать.
Клиент адресуется **кодом** (`K7F3Q2`; 6 символов алфавита без 0/O/1/I), а не id: у
Telegram-клиента id — это его Telegram ID.

Доступ к клиенту (`manager_clients`) появляется тремя способами:

- менеджер сам завёл клиента (офлайн-клиент без Telegram и email);
- клиент продиктовал **одноразовый код** (бот: профиль → «👔 Код для менеджера»; сайт: кабинет →
  «Помощь менеджера»; живёт 15 минут, неверные вводы — не более 5 в час на менеджера);
- конвертация временного ключа в подписку.

Доступ ограничен по сроку (конец подписки + `manager_access_grace_days`, минимум сутки) и
отзывается клиентом в любой момент (кнопка в уведомлении «менеджер получил доступ»,
кабинет). Чужой и несуществующий код неотличимы — для разведки он не годится.

Менеджер видит **белый список** (`ClientCard`): код, метка, статус и срок подписки,
устройства (сколько из скольких + платформы, **без hwid и IP**), трафик, докупленное,
свои операции по клиенту. Не видит: Telegram ID, username, email, платёжные данные,
историю платежей, рефералов, ссылку подписки (кроме явного просмотра — он пишется в журнал).
Набор полей зафиксирован тестом `tests/test_manager_service.py::PrivacyTests`.

Менеджер ничего не меняет напрямую: отвязать устройство, перевыпустить ключ, удалить клиента
он не может — только операции из списка ниже, и все они в журнале.

## Журнал и чеки

`manager_operations` — только INSERT и смена статуса. Типы: `issue_tariff`, `issue_custom`,
`issue_temp`, `convert_temp`, `access_grant`, `key_view`, `autorenew_off`,
`cabinet_link_reset`. Для каждой записи: менеджер, время, тип, клиент (код), тариф/дни, срок
действия ключа, цена, способ оплаты, идентификация ключа (имя в панели + отпечаток из 4 hex).
Снимки полей после создания не перезаписываются (`MUTABLE_FIELDS`).

Чек в группе (`MANAGER_LOG_CHAT_ID` / `MANAGER_LOG_TOPIC_ID`; не заданы — туда же, куда лог
транзакций) выглядит так и **не содержит ссылки подписки, Telegram ID и контактов**:

```
🧾 Чек № M-000123 · 01.10.2026 14:32 МСК
👔 Менеджер: Иван П. (#7)
👤 Клиент: K7F3Q2 (новый)
📦 Месяц · 30 дн.
📊 500 ГБ/мес · 📱 до 5 устр.
📅 Действует до 31.10.2026 14:32
💰 Итого: 149 ₽
💵 Наличные · к сдаче у менеджера: 1 250 ₽
🔑 Ключ: off_k7f3q2 · …3f9a
✅ Ключ выдан
```

Одно сообщение живёт всю операцию: «⏳ Ждём оплату» → «✅ Ключ выдан» → (для временного)
«🗑 Ключ удалён 15:35» / «↩️ Оплата возвращена клиенту». Чек **не фискальный**: при онлайн-оплате
фискальный чек выбивает ЮKassa.

**Чек — картинка и текст одним сообщением, везде** (группа, менеджер, Telegram-клиент): PNG
(`tgbot/services/receipt_image.py`, Pillow, шрифты `tools/fonts`, бренд-бук) + текст чека подписью.
Живой статус в группе правится `edit_message_media` (картинка со штампом и подпись вместе); старые
текстовые чеки, которые фото не станут, публикуются заново. Подпись Telegram — до 1024 символов:
длиннее — сначала убирается ссылка установки (она есть QR на картинке), потом текст режется
(`manager_notifier.fit_caption`). Картинка не нарисовалась — уходит один текст.

| Адресат | Картинка |
|---|---|
| группа | без QR и пометки клиента; имя ключа и отпечаток — для сверки |
| менеджер | с пометкой и QR установки (это и есть «Покажите клиенту») |
| Telegram-клиент | продукт, срок, разбивка суммы, QR установки |

На сайте: `GET /manager/receipt/<id>.png` (только своя операция, `?download=1` — скачать), чек
под результатом продажи с кнопками «Скачать чек» / «Отправить клиенту» (Web Share), ссылки в истории.
Клиент (в т.ч. офлайн по ссылке `/c/…`) видит «Чеки покупок у менеджера» в кабинете —
`GET /profile/receipt/<id>.png`.

## Услуга менеджера

Каждый менеджер задаёт цену своей услуги — **подключение и настройка VPN** (`managers.service_fee`,
по умолчанию 250 ₽, 0…1000): бот «💼 Моя услуга», сайт «Аккаунт». Админ может задать цену сам и
зафиксировать её (`service_fee_locked`, «🔒 Зафиксировать цену» в карточке) — тогда менеджер её не меняет.
Смена цены сессии не сбрасывает.

- Входит в каждую продажу: тариф, любой срок, подписка на пробный ключ (пробный ключ — бесплатно,
  без услуги). `quote.total = подписка + услуга`, в превью, текстовом чеке и картинке — отдельной строкой.
- **Услугу клиент всегда отдаёт менеджеру наличными.** При оплате по QR счёт ЮKassa — только подписка
  (`quote.subscription_total`), в фискальном чеке ЮKassa услуги нет. Операция помечается
  `manager_operations.fee_in_cash`, `IssueResult.fee_cash` — сколько взять наличными (бот и сайт пишут это
  на экране счёта), в нашем чеке строка «Подключение VPN (наличными)».
- Снимок — `manager_operations.service_fee` (внутри `price`); в журнале и CSV — свой столбец.
- **Автопродление — только подписка**: `charge_renewal` считает цену по тарифу, услуга в нём не участвует
  (это же сказано в тексте согласия и в оферте §4).
- **Наличные**: услуга остаётся у менеджера — «к сдаче», лимит наличных и инкассация считают `price − service_fee`.
- **QR**: подписка приходит магазину, услуга — наличными менеджеру; ни в «к сдаче», ни «к выплате» она не
  попадает. «К выплате менеджеру» (`fees_outstanding`: онлайн, completed, `fee_in_cash = false`,
  `fee_paid_at IS NULL`) копится только по **старым** QR-продажам, где услуга шла через ЮKassa. Админ:
  «💸 Выплатить N ₽» → `manager_payouts`, операции получают `fee_paid_at`, менеджеру — уведомление.
- **Партнёры**: процент партнёру считается от денег магазина — услуга из суммы оплаты вычитается только там,
  где она в оплате есть (наличные и старые QR), `PartnerRepository.manager_fee_for_payment`.
- **Возврат** (вебхук `refund.succeeded`) → операция `refunded`, услуга выпадает из «к выплате» и из
  заработка. Если её уже выплатили — ERROR в лог (удержать при следующей выплате вручную).
- Заработок — `PeriodStats.fees` (бот: меню и статистика, сайт: главная, админ: карточка).
- **Расширенная статистика админа**: продажи менеджеров (`Payment.source` = `manager`/`cash`) в общий «Доход»
  не входят — отдельный блок по тем же периодам, деньги магазина без услуги, QR и наличные раздельно, услуги
  менеджеров — справочной строкой (`PaymentRepository.get_manager_sales`).

## Оплата

- **QR / онлайн (по умолчанию).** Клиент платит СБП или картой со своего телефона, ключ
  выдаётся сам по вебхуку, карта сохраняется и **автопродление включено** (если магазин
  одобрил рекурренты — `YOOKASSA_SAVE_PAYMENT_METHOD=True`). Текст согласия менеджер видит
  в предпросмотре, клиент — на странице оплаты.
- **Наличные** — только менеджерам с `can_accept_cash`. Сумма идёт в «к сдаче»; потолок
  `cash_limit` (по умолчанию 5000 ₽) блокирует новые наличные продажи, пока админ не примет
  выручку («💰 Принять выручку» в карточке менеджера). Неудачные операции в «к сдаче» не попадают.

Наличная продажа проходит через тот же конвейер, что и онлайн (`Payment(source='cash')` →
`process_successful_payment`): продление, слоты, трафик, флаг первой оплаты и бонус рефереру
работают одинаково во всех каналах.

⚠️ Наличные без кассы — юридический риск (54-ФЗ). Решение (касса / самозанятость / только
онлайн) за владельцем: система только ведёт учёт.

## Клиенты без Telegram

Менеджер создаёт офлайн-клиента: отрицательный id в диапазоне −2·10⁹…−10⁹ (не пересекается
с веб-пользователями), `origin='offline'`, код, ключ `off_<код>`. Клиенту достаётся
**ссылка кабинета** `https://<домен>/c/<токен>` (показывается один раз; в БД — sha256):
по ней он видит подписку, продлевает и отключает автопродление. Потерял ссылку — менеджер
перевыпускает («🔗 Новая ссылка кабинета»), старая сразу мертва.
Телеграм-рассылки такие клиенты не получают (`is_active=False`, id < 0); о скорой потере
подписки менеджера предупреждает ежедневный дайджест (11:00).

## Свои дни: формула цены

```
цена(d) = округление_вверх_до_…9( max(
    мин_чек,
    цена_дня × (d + K × √d),            # база + надбавка за короткий срок
    max{цена тарифа T : дни(T) ≤ d},    # не дешевле более короткого тарифа
    d × min(цена(T) / дни(T))           # не дешевле лучшего тарифа за день
))
```

По умолчанию: цена дня 5 ₽, K = 1.5, минимум 59 ₽, 1…365 дней (`app_settings`:
`custom_day_price`, `custom_short_premium`, `custom_min_price`, `custom_max_days`).
Свойства (проверяются тестами на d = 1…365): цена монотонна; «свой» день всегда дороже дня
в лучшем стандартном тарифе; нет инверсий «29 дн. дороже 30». Менеджер видит разложение цены и
подсказку «выгоднее тариф X, на N ₽ дешевле» — клиента естественно вести на тариф с
автопродлением. Админка: «💲 Свои дни и врем. ключи» — настройки и таблица-превью.

После «своих дней» карта продлевает **обычный тариф** (`custom_renew_tariff_id`; не задан —
ближайший к 30 дням). Это же написано в тексте согласия.

Пример для тарифов 74 ₽/7 дн., 149 ₽/30 дн., 399 ₽/90 дн.:

| дней | 1 | 7 | 14 | 30 | 45 | 90 | 365 |
|---|---|---|---|---|---|---|---|
| ₽ | 59 | 79 | 99 | 199 | 279 | 529 | 1969 |

## Как это выглядит для менеджера

**Руководство для менеджеров** — `docs/manager-guide.pdf` (12 стр., крупный шрифт, снимки бота и сайта). Собирается
`./tools/manager_guide/build.sh` со стенда на демо-данных (`stand.py` — SQLite и сценарии бота через тестовое окружение,
`capture.py` — снимки через playwright и системный Chrome, `content.py` — текст). После правок интерфейса
или текстов — пересобрать.

Одни и те же сценарии и слова в боте и на сайте; сайт сделан под телефон (нижняя панель вкладок).
Тексты памятки и подсказок — одним источником в `tgbot/services/manager_guide.py`.

- **Быстрая продажа.** Главный экран бота (`/manager`) и сайта (`/manager/`) — кнопки тарифов с ценой:
  одно нажатие = новый клиент + тариф, дальше экран оплаты (`mgr:q:<id>`, `mgr:q:custom`; сайт —
  `/manager/issue?tariff=<id>` / `?custom=1`). Продление своему клиенту и клиент по коду — отдельными
  кнопками, старый мастер (`mgr:issue` → кому → что) остался.
- **Устройства и трафик при продаже (сайт).** На странице продажи — счётчики «Устройства» и «Трафик в месяц»:
  менеджер добавляет клиенту доп. устройства и пакеты трафика на новый срок, цена пересчитывается сразу.
  По умолчанию — как у клиента сейчас (у нового — ничего), уменьшить при продлении тоже можно. Потолки —
  админские `max_extra_devices` / `max_traffic_packs` (вне — `bad_extras`), у безлимитного тарифа трафика нет.
  Сервис: `quote(..., slots=, packs=)` / `issue(..., slots=, packs=)`, API — поля `slots` / `packs`.
  Платёж применяет их абсолютно (как чекаут бота), автопродление дальше включает их в сумму.
- **«Любой срок»** — так теперь называются «свои дни» в интерфейсе и чеках (`CUSTOM_PRODUCT_NAME`);
  частые сроки — кнопками (7/14/45/60/90/180 дн.), остальное — числом.
- **Пробный ключ** — так в интерфейсе называется временный ключ. За 10 минут до конца менеджеру
  приходит напоминание с кнопкой «Оформить подписку на этот ключ» (`remind_expiring_temp_keys`,
  внутри джоба `expire_temp_keys`, по ключу один раз — `temp_keys.reminded_at`).
- **Пометка о клиенте** при продаже (необязательно): «Анна, кофейня» — `manager_clients.label`,
  видна менеджеру и админу, в чеке менеджера есть, в групповом чеке и у клиента — нет. Меняется в карточке.
  В списке клиентов пометка — заголовок строки, есть поиск по пометке и коду.
- **«Покажите клиенту».** После выдачи — большой QR установки с шагами для клиента (бот — фото с
  подписью, сайт — экран на весь дисплей); новому клиенту — ещё QR личного кабинета.
  В чеке менеджера нет технического имени ключа и отпечатка (они остались в групповом чеке для сверки).
- **Живой статус счёта.** Сообщение со счётом в боте само меняется на «✅ Оплачено» / «🚫 Счёт отменён»
  (`manager_operations.invoice_chat_id/message_id`, `ManagerService._mark_invoice`); кнопки «Проверить
  оплату» больше нет (старые кнопки работают). Сайт опрашивает статус и после оплаты сразу показывает QR установки.
- **Памятка «Как продавать»** — бот `mgr:help`, сайт `/manager/help`; новичку на неё указывает
  приветствие после приглашения и баннер на главной, пока нет ни одной операции.

## Временный (пробный) ключ

По умолчанию 60 минут, 5 ГБ, 1 устройство (`temp_key_minutes`, `temp_key_traffic_gb`,
`temp_key_devices`), лимит на менеджера — `temp_keys_per_day` (5). Пользователь панели
`tmp_xxxxxxxx` с `description="temp · manager #N · op #M"`; чек в группу — на каждый ключ.
Джоб `expire_temp_keys` (каждую минуту) удаляет истёкшие ключи из панели: 404 панели — успех,
сетевая ошибка — повтор; после 5 неудач в лог уходит ERROR (он улетает админам) — ключ,
который обязан был умереть, продолжает работать.

**Конвертация:** «💳 Оформить подписку на этот ключ» — клиентом становится владелец ключа, а
пользователь панели остаётся прежним: подписка продлевается на нём, ссылка не меняется,
переустанавливать ничего не нужно. Не оплатили за 30 минут после истечения — ключ удаляется.

## Докупка трафика

Базовая квота — **500 ГБ/мес** (`base_traffic_gb`). У тарифа `data_limit_gb`: NULL → базовая,
0 → безлимит, N → N. (Раньше NULL означал безлимит — после обновления тарифы без явного
лимита получают 500 ГБ при **следующей оплате**; действующим подписчикам лимит до
продления не режется.)

Пакеты — как доп. устройства: +100 ГБ/мес за 49 ₽/мес (`traffic_pack_gb`, `traffic_pack_price`,
`max_traffic_packs`=10). В чекауте: `цена × месяцев × пакетов`; в середине срока — по остатку
дней, но не дешевле месячной. Докупленное действует до конца подписки, продлевается вместе с
ней (автосписание включает пакеты), промокод на него не действует, Stars не принимаются.
Лимит в панели — абсолютное `квота + докупленное`; статус LIMITED панель снимает сама при
повышении лимита. Где: бот (профиль → «📊 Докупить трафик», степпер на чекауте), сайт
(`POST /payment/traffic`, степпер в тарифах), Mini App. Джобы: `sync_traffic_limits` (час),
`traffic_usage_alerts` (90% и 100%). Админка: «📊 Трафик».

## Фоновые джобы

| Джоб | Когда | Что |
|---|---|---|
| `expire_temp_keys` | каждую минуту | напоминает о скором конце пробного ключа (за 10 мин), удаляет истёкшие |
| `sync_manager_operations` | каждые 2 мин | отменённый счёт → операция отменена; оплаченный, но не доведённый → доводит |
| `manager_renewal_digest` | 11:00 | менеджеру — его клиенты без автопродления, подписка кончается ≤ 3 дн. |
| `sync_traffic_limits` | :25 каждого часа | доводит лимит трафика до БД, гасит пакеты после конца подписки |
| `traffic_usage_alerts` | 9–21 каждые 3 ч | предупреждения на 90% и 100% квоты |

## Деплой

```bash
python3 fix_db.py          # секции 17 (трафик), 18–21 и 23 (менеджеры, услуга, выплаты, fee_in_cash): ALTER ... IF NOT EXISTS, create_all
# .env (необязательно): MANAGER_LOG_CHAT_ID, MANAGER_LOG_TOPIC_ID
./refresh.sh               # бот и сайт
```

В группу для чеков добавьте бота (право писать; для топика — `MANAGER_LOG_TOPIC_ID`).
После деплоя проверьте: `/admin` → «👔 Менеджеры» → пригласить тестового менеджера → выдать
временный ключ с `temp_key_minutes=2` → через 2–3 минуты ключ исчез из панели, а чек в группе
дополнился строкой «🗑 Ключ удалён».
